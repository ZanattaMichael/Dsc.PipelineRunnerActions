# Contributing

## Layout

| Path | What |
| --- | --- |
| `core/Invoke-DscPipelineRunnerStep.ps1` | The step. All behaviour lives here. |
| `core/settings.json` | The one list of settings and outputs. |
| `action.yml` | GitHub Action (must be at the repository root for the Marketplace). |
| `azure-devops/` | Extension manifest, task (`task.json`, `index.js`), Marketplace page (`overview.md`). |
| `templates/dsc-pipeline-runner.yml` | GitLab component (must be in `templates/` at the root). |
| `circleci/orb.yml` | CircleCI orb. |
| `jenkins/` | Shared library: `vars/` and a committed copy of `core/` in `resources/`. |
| `examples/` | A complete pipeline per platform. |
| `assets/` | Logos and README headers, generated by `tools/build-logos.js`. |
| `tools/` | `Sync-Core.ps1`, `Build-SettingsDoc.ps1`, `Set-AzureDevOpsVersion.ps1`, `build-logos.js`. |
| `tests/` | Pester tests and the stand-in module. |
| `.github/workflows/` | CI, the release pipeline and one publish pipeline per registry. |
| `.gitlab-ci.yml` | Pipeline of the GitLab project that hosts the component. |

## Tests

```powershell
Invoke-Pester -Path tests
```

```bash
node --test azure-devops/tests/index.test.js
```

| File | What it covers |
| --- | --- |
| `tests/Step.tests.ps1` | The step's main paths: validation in one pass, what is shown, what reaches the runner, outputs and exit codes. |
| `tests/Step.Behaviour.tests.ps1` | Platform detection and annotations, each setting's validation, warnings, error-preference handling, what is left on disk. |
| `tests/Step.Install.tests.ps1` | Installing and choosing module versions, retries, `skip-module-install`. `Install-Module` is mocked. |
| `tests/Step.Source.tests.ps1` | `module-source: Repository`, against a local git repository the test creates: refs, the build, dependencies. |
| `tests/Integrations.tests.ps1` | Every integration offers every setting with the same default; secrets are never plain settings; generated files are current. |
| `tests/Examples.tests.ps1` | Every example pipeline and documentation snippet uses only settings that exist; relative links resolve; the GitLab and CircleCI command is shell-agnostic. |
| `tests/Tools.tests.ps1` | The scripts in `tools/`, run on a copy of the repository, and the shape of `core/settings.json`. |
| `azure-devops/tests/index.test.js` | The Azure DevOps task entry point: input mapping, undefined variables, a missing PowerShell, `task.json`. |
| `tests/integration/azure-devops/` | The packaged Azure DevOps task, run the way an agent runs it, case by case; and the same cases on a real agent where an organization is configured. See its [README](../tests/integration/azure-devops/README.md). |
| `tests/integration/jenkins/` | The Jenkins shared library in a real Jenkins controller in Docker. |

None of these need the network. The step tests run against stand-in modules in `tests/fixtures/`
that record the arguments they received; `tests/TestHelpers.ps1` holds the shared helpers.

CI also runs the GitHub Action for real, packages the Azure DevOps extension and runs its
integration cases against the package, runs the action once against the real module from the PowerShell Gallery, and builds
the module from source on Windows and Linux.

## Adding or changing a setting

1. Edit `core/settings.json`.
2. Use it in `core/Invoke-DscPipelineRunnerStep.ps1`.
3. Add it to `action.yml`, `azure-devops/DscPipelineRunnerTask/task.json` and `index.js`,
   `templates/dsc-pipeline-runner.yml`, `circleci/orb.yml` (command, job and pass-through) and
   `jenkins/vars/dscPipelineRunner.groovy`.
4. Run `tools/Sync-Core.ps1` and `tools/Build-SettingsDoc.ps1`.
5. Run the tests; they name any integration you missed.
